= DwarFS Backend Documentation
:toc:
:toclevels: 3

== Overview

The DwarFS backend provides read-only access to DwarFS archives through the unified [`FileSystem`](../../include/tebako/fs/filesystem.h) interface using libdwarfs v0.9+.

DwarFS is a highly compressed read-only filesystem format optimized for:

* **Superior compression ratios** - significantly better than ZIP or SquashFS
* **Fast random access** - native seek support without file reopening
* **Low memory overhead** - efficient deduplication and compression
* **Metadata preservation** - full POSIX permissions and timestamps

== Architecture

The DwarFS backend consists of three main classes that implement the VFS abstraction layer.

=== DwarfsBackend

Main backend class implementing the [`FileSystem`](../../include/tebako/fs/filesystem.h) interface.

.Class Declaration
[source,cpp]
----
class DwarfsBackend : public FileSystem {
 public:
  DwarfsBackend();
  ~DwarfsBackend() override;

  // Lifecycle methods
  bool mount(const std::string& archive_path,
             const std::string& mount_point) override;
  bool mount_from_memory(const void* data, size_t size,
                        const std::string& mount_point) override;
  void unmount() override;
  bool is_mounted() const override;

  // File operations
  std::unique_ptr<FileHandle> open(const std::string& path,
                                    int flags) override;
  bool exists(const std::string& path) const override;
  bool is_file(const std::string& path) const override;
  bool is_directory(const std::string& path) const override;

  // Directory operations
  std::unique_ptr<DirectoryIterator> list_directory(
      const std::string& path) override;

  // Metadata operations
  int64_t file_size(const std::string& path) const override;
  time_t modification_time(const std::string& path) const override;
  mode_t permissions(const std::string& path) const override;

  // Backend info
  std::string backend_name() const override;
  std::string backend_version() const override;
  std::string archive_path() const override;
  std::string mount_point() const override;

 private:
  class Impl;  // PIMPL to hide DwarFS library details
  std::unique_ptr<Impl> impl_;
  mutable std::shared_mutex mutex_;
  std::string archive_path_;
  std::string mount_point_;
};
----

.Key Responsibilities
* Archive mounting from file or memory
* Path resolution and inode lookup
* Thread-safe access to DwarFS filesystem
* Resource cleanup on unmount
* PIMPL pattern to hide library implementation details

=== DwarfsFileHandle

Implements [`FileHandle`](../../include/tebako/fs/file_handle.h) for reading files from DwarFS archives.

.Features
* **Native random access** - DwarFS supports seeking without file reopening
* Sequential reading with efficient buffering
* Position tracking ([`tell()`](../../include/tebako/fs/file_handle.h:45))
* EOF detection ([`eof()`](../../include/tebako/fs/file_handle.h:52))
* Thread-safe file operations

.Seek Implementation
Unlike ZIP, DwarFS supports native seeking. This provides significant performance benefits:

[source,cpp]
----
off_t DwarfsFileHandle::seek(off_t offset, int whence) {
  // Calculate target position
  off_t target = calculate_target_position(offset, whence);

  // DwarFS supports native seek - no reopening needed!
  current_pos_ = target;
  eof_ = (current_pos_ >= size_);

  return current_pos_;
}
----

This approach provides **< 0.1 ms** seek overhead compared to ZIP's 5-20 ms reopen strategy.

=== DwarfsDirectoryIterator

Implements [`DirectoryIterator`](../../include/tebako/fs/directory_iterator.h) for traversing directories.

.Capabilities
* Iterates entries at a specific directory level
* Pre-loads entries for fast iteration
* Provides comprehensive metadata ([`DirectoryEntry`](../../include/tebako/fs/directory_iterator.h:42) structure)
* Supports reset for re-iteration
* Thread-safe iteration

== Usage Examples

=== Basic File Reading

[source,cpp]
----
#include <tebako/fs/backend_factory.h>

using namespace tebako::fs;

// Create backend
auto backend = BackendFactory::create_dwarfs();

// Mount archive
if (backend->mount("archive.dwarfs", "/mnt/app")) {
  // Open file
  auto handle = backend->open("/mnt/app/file.txt", O_RDONLY);
  if (handle) {
    // Read content
    char buffer[1024];
    ssize_t bytes = handle->read(buffer, sizeof(buffer));

    // Process data
    std::cout.write(buffer, bytes);
  }

  // Unmount when done
  backend->unmount();
}
----

=== Memory Mounting

[source,cpp]
----
// DwarFS archives can be embedded in executables
extern const uint8_t embedded_dwarfs[];
extern const size_t embedded_dwarfs_size;

auto backend = BackendFactory::create_dwarfs();

// Mount from memory
if (backend->mount_from_memory(embedded_dwarfs,
                                embedded_dwarfs_size,
                                "/__tebako__")) {
  // Use filesystem as normal
  auto handle = backend->open("/__tebako__/config.yaml", O_RDONLY);
  // ... read configuration ...

  backend->unmount();
}
----

=== Random Access Reading

[source,cpp]
----
auto backend = BackendFactory::create_dwarfs();
if (backend->mount("data.dwarfs", "/mnt/data")) {
  auto handle = backend->open("/mnt/data/binary.dat", O_RDONLY);

  // Seek to specific offset (fast with DwarFS!)
  handle->seek(1024 * 1024, SEEK_SET);  // 1 MB offset

  // Read chunk
  char buffer[4096];
  handle->read(buffer, sizeof(buffer));

  // Seek backwards
  handle->seek(-2048, SEEK_CUR);

  // Read another chunk
  handle->read(buffer, sizeof(buffer));

  backend->unmount();
}
----

=== Directory Traversal

[source,cpp]
----
auto backend = BackendFactory::create_dwarfs();
if (backend->mount("archive.dwarfs", "/mnt/app")) {
  // List directory
  auto iter = backend->list_directory("/mnt/app/docs");

  while (iter && iter->has_next()) {
    auto entry = iter->next();

    std::cout << entry.name;
    if (entry.is_directory) {
      std::cout << " (directory)";
    } else {
      std::cout << " (" << entry.size << " bytes)";
    }
    std::cout << std::endl;
  }

  backend->unmount();
}
----

=== File Metadata

[source,cpp]
----
auto backend = BackendFactory::create_dwarfs();
if (backend->mount("archive.dwarfs", "/mnt/app")) {
  std::string path = "/mnt/app/document.pdf";

  // Check existence
  if (backend->exists(path)) {
    // Get metadata (preserved from original filesystem)
    int64_t size = backend->file_size(path);
    time_t mtime = backend->modification_time(path);
    mode_t perms = backend->permissions(path);

    std::cout << "Size: " << size << " bytes" << std::endl;
    std::cout << "Modified: " << std::ctime(&mtime);
    std::cout << "Permissions: " << std::oct << perms << std::endl;
  }

  backend->unmount();
}
----

=== Concurrent Access

The backend uses [`std::shared_mutex`](../../src/backends/dwarfs_backend.cpp:60) for thread-safe access:

* **Read operations**: Multiple threads can read simultaneously with **no serialization**
* **Write operations**: N/A (read-only backend)
* **Mount/unmount**: Exclusive access required

== Thread Safety

The backend implements comprehensive thread safety:

=== Read Operations

Multiple threads can safely:

* Open different files simultaneously (**no serialization needed**)
* Read from different [`FileHandle`](../../include/tebako/fs/file_handle.h) instances
* List directories concurrently
* Query file metadata
* Perform random seeks

=== Advantages

* **No libzip-style limitations** - DwarFS reader is fully thread-safe
* **True concurrent file opening** - unlike ZIP backend
* **Efficient multi-threaded access** - ideal for parallel workloads
* Each thread uses separate handles for maximum performance

== Known Limitations

=== DwarFS Format Limitations

==== Read-Only Access

The backend does not support:

* Writing new files
* Modifying existing files
* Deleting files
* Creating directories

This is by design for the Tebako use case and matches the DwarFS format specification.

==== Image Offset Auto-Detection

DwarFS supports embedding archives in executables with automatic offset detection:

* Archives can be appended to executables
* Library automatically finds DwarFS magic bytes
* No manual offset specification required

==== Compression Algorithms

DwarFS supports multiple compression algorithms:

* LZMA (default) - best compression
* LZ4 - fastest decompression
* ZSTD - balanced performance

The backend works with any compression algorithm used in the archive.

=== Library Requirements

==== Minimum Version

Requires DwarFS library v0.9.0 or later:

* Earlier versions use different API
* v0.9+ provides `filesystem_v2` interface
* Recommended: Latest stable release

==== Memory Usage

* **Lower than ZIP** - excellent deduplication
* Each open file: minimal overhead (~1-2 KB)
* Metadata: Cached efficiently by library
* Recommendation: No specific limit on concurrent files

== Implementation Details

=== PIMPL Pattern

The backend uses PIMPL (Pointer to Implementation) to hide DwarFS library details:

[source,cpp]
----
class DwarfsBackend::Impl {
 public:
  Impl();
  ~Impl();

  bool mount_file(const std::string& archive_path);
  bool mount_memory(const void* data, size_t size);
  void unmount();
  bool is_mounted() const;
  dwarfs::reader::filesystem_v2* get_fs();
  std::optional<dwarfs::reader::inode_view> find_inode(const std::string& path);

 private:
  bool is_mounted_;
  std::shared_ptr<dwarfs::stream_logger> logger_;
  std::unique_ptr<dwarfs::reader::filesystem_v2> fs_;
};
----

This design:

* Hides DwarFS headers from public API
* Allows library version changes without recompilation
* Reduces compilation dependencies
* Improves build times

=== Path Handling

The backend normalizes paths before DwarFS operations:

[source,cpp]
----
std::string DwarfsBackend::normalize_path(const std::string& path) const {
  // Remove mount point prefix
  std::string rel_path = strip_mount_point(path);

  // Remove leading slash (DwarFS uses relative paths)
  if (!rel_path.empty() && rel_path[0] == '/') {
    rel_path = rel_path.substr(1);
  }

  // Empty path means root
  if (rel_path.empty()) {
    return "";
  }

  // Clean up "./" segments
  // ... normalization logic ...

  return rel_path;
}
----

=== Inode-Based Access

DwarFS uses inode-based file access:

[source,cpp]
----
// Find inode for path
auto inode_opt = impl_->find_inode(normalized_path);
if (!inode_opt) {
  return nullptr;  // File not found
}

// Get file attributes via inode
std::error_code ec;
auto stat = impl_->get_fs()->getattr(*inode_opt, ec);

// Read file data via inode
int bytes_read = impl_->get_fs()->read(
    inode_opt->inode_num(),
    buffer,
    count,
    offset);
----

This provides very fast lookups and efficient file access.

=== Error Handling

All operations return appropriate error indicators:

* [`open()`](../../include/tebako/fs/filesystem.h:89): Returns `nullptr` on failure
* [`mount()`](../../include/tebako/fs/filesystem.h:82): Returns `false` on failure
* [`file_size()`](../../include/tebako/fs/filesystem.h:132): Returns `-1` on error
* [`list_directory()`](../../include/tebako/fs/filesystem.h:118): Returns `nullptr` on failure

Errors are logged but not thrown, maintaining C compatibility.

=== Resource Management

The backend uses RAII for resource management:

* DwarFS filesystem closed in destructor
* Logger lifecycle managed automatically
* Mutex released automatically via guard
* Memory file views use shared_ptr for safety
* No manual memory management required
