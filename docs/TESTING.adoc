== Test Organization

=== Test Suite Structure

Each test suite focuses on a specific layer of the system:

. **test_backend_factory**: Backend abstraction and factory pattern
. **test_zip_backend**: ZIP backend implementation details
. **test_zip_integration**: Factory + backend integration
. **test_c_api**: C interface for Ruby integration

=== Test Categories

==== Format Detection (11 tests)
* Magic byte validation (DwarFS, ZIP, SquashFS)
* Extension-based fallback
* Error handling for invalid formats

==== File Operations (31 tests)
* open(), read(), seek(), close()
* Error handling (invalid FD, null buffers)
* Edge cases (empty files, large files)
* Performance benchmarks

==== Directory Operations (18 tests)

* Concurrent access

==== Metadata Operations (12 tests)

* Double-mount prevention

* Memory mounting validation

==== Thread Safety (8 tests)
* Concurrent reads
* Concurrent directory listings
* FD independence
* DIR handle independence

==== C API Compatibility (46 tests)
* All POSIX-like operations
* Error code propagation
* Path detection
* FD flag checking

== Test Fixtures

=== ZIP Fixtures

Location: [`tests/fixtures/zip/`](../tests/fixtures/zip/)

Required files:
* `simple.zip` - Basic ZIP with single file (test.txt)
* `nested.zip` - ZIP with nested directories
* `corrupted.zip` - Invalid ZIP for error testing

Fixtures are automatically copied to build directory during configuration.

=== Creating Test Fixtures

[source,bash]
----
# Create simple test archive
echo "Hello from ZIP!" > test.txt
zip simple.zip test.txt

# Create nested structure
mkdir -p dir1/dir2
echo "Nested file" > dir1/dir2/file.txt
zip -r nested.zip dir1/

# Create corrupted file (invalid magic bytes)
printf '\xFF\xFF\xFF\xFF\x00\x00\x00\x00' > corrupted.zip
----

== Debugging Test Failures

=== Common Issues

==== Test Fixture Not Found

[source,bash]
----
# Verify fixtures copied
ls -la build/tests/fixtures/zip/

# Recopy if needed
cmake --build build --target clean
cmake ..
----

==== Linking Errors

[source,bash]
----
# Check library dependencies
nm build/test_c_api | grep " U "

# Verify all libraries linked
ldd build/test_c_api  # Linux
otool -L build/test_c_api  # macOS
----

==== Segmentation Faults

[source,bash]
----
# Run with debugger
lldb build/test_c_api
(lldb) run --gtest_filter=CApiTest.Open_ValidFile

# Run with address sanitizer
cmake -B build -DWITH_ASAN=ON
cmake --build build
./build/test_c_api
----

==== Random Failures

[source,bash]
----
# Run test multiple times
for i in {1..10}; do
  ./test_backend_factory || break
done

# Check for race conditions
./test_zip_backend --gtest_repeat=100
----

=== Verbose Test Output

[source,bash]
----
# Individual test with full output
./test_c_api --gtest_filter=CApiTest.Read_Success --gtest_verbose=1

# CTest verbose mode
ctest -VV -R test_backend_factory
----

== Test Development Guidelines

=== Adding New Tests

. Create test in appropriate suite file
. Follow naming convention: `TestSuite.TestName`
. Use ASSERT_* for fatal checks, EXPECT_* for non-fatal
. Clean up resources in test teardown

[source,cpp]
----
TEST_F(ZipBackendTest, NewFeature) {
  // Setup
  auto backend = create_mounted_backend();

  // Execute
  auto result = backend->new_feature();

  // Verify
  ASSERT_NE(result, nullptr);
  EXPECT_EQ(result->value(), expected);

  // Teardown handled by fixture
}
----

=== Test Fixtures

Use test fixtures for common setup/teardown:

[source,cpp],
----
class MyTest : public ::testing::Test {
 protected:
  void SetUp() override {
    // Common initialization
  }

  void TearDown() override {
    // Common cleanup
  }

  // Shared test data
  std::string test_path;
};
----

=== Running Subsets

[source,bash]
----
# Run only file operation tests
./test_c_api --gtest_filter=CApiTest.Open_*

# Run all except slow tests
./test_zip_backend --gtest_filter=-*.Performance*

# List available tests
./test_backend_factory --gtest_list_tests
----

== Known Limitations

=== Platform-Specific

* **SquashFS**: Only available on Linux (squashfs-tools-ng)
* **Link tests**: Disabled on Windows platforms
* **Performance tests**: May vary by system load

=== Implementation Gaps

* **DwarFS backend**: Not yet implemented (auto-detection works)
* **Write operations**: All backends are read-only
* **Symbolic links**: Limited support in some backends

cd build && ctest
----
